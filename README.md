# EFO-Plutchik

**An [EFO](https://arxiv.org/abs/2401.10751)-compatible ontology module for Plutchik's wheel of emotions, with a machine-checkable validation layer.**

- Namespace: `https://w3id.org/efo-plutchik#` (prefix `plu:`)
- Version: 0.9.0 (2026-11-28; mapping module 0.7.0 adds 9 datasets, with the records of the 12 earlier datasets unchanged; transfer-evidence module 0.3.0 adds a third study; core ontology 0.5.0 is unchanged) · License: CC BY 4.0 (ontology/docs) + Apache-2.0 (code) — see [LICENSE](LICENSE)
- Verification: fully local, no training / no GPU / no `torch`.
- Documentation: <https://kotafuse-labs.github.io/efo-plutchik/> (every term; generated by `scripts/build_docs.py`)

This is the **lean, publication-oriented package** of the ontology: the TBox, the
inference layer, the SHACL/CQ verification layer, and the code needed to *run the
checks*. Machine-learning experiments that consume this ontology are maintained
separately (see [Related work](#related-work)); none of that code is included here.

---

## What is in the ontology

Plutchik's theory is encoded as **TBox + emotion individuals + derivation rules**:

- **8 basic emotions** — Anger, Anticipation, Disgust, Fear, Joy, Sadness, Surprise, Trust
- **4 opposition pairs** (`plu:hasOpposite`, symmetric) — Joy↔Sadness, Trust↔Disgust, Fear↔Anger, Surprise↔Anticipation
- **Wheel geometry** (`plu:wheelPosition` 0–7, `plu:isAdjacentTo`) — the circular distance of two basic emotions (1/2/3/4) decides primary / secondary / tertiary dyad or opposites
- **16 intensity variants** (`plu:intensityOf`, `plu:hasIntensityLevel` low / medium / high) — e.g. Serenity < Joy < Ecstasy, Annoyance < Anger < Rage
- **24 dyads** (`plu:hasComponentEmotion`) — 8 primary (e.g. `Love = Joy + Trust`), 8 secondary (e.g. `Pride = Anger + Joy`), 8 tertiary (e.g. `Pessimism = Sadness + Anticipation`), after Plutchik (2001)
- **VAD vocabulary** (`plu:VADReading`, `plu:vadValence` / `vadArousal` / `vadDominance`) — values are *not* shipped (NRC VAD is research / non-commercial); `ontology/build_vad.py` generates them locally from a lexicon you obtain yourself
- **Dataset label mappings** (`ontology/plutchik-mappings.ttl`, generated by `build_mappings.py`) — two schemes: Lim & Cheong (2024) components for SemEval-2018 E-c and GoEmotions (kept for reproduction, audited), and a Plutchik (2001) name-based scheme for 21 datasets (the two above plus EmpatheticDialogues, crowd-enVENT, GoodNewsEveryone, BRIGHTER English, XED, SSEC, enISEAR, DailyDialog, SemEval-2018 EI-oc and Electoral Tweets; since 0.7.0 also ISEAR, CBET, CARER, TEC, MELD, Real World Worry, SenWave English, StockEmotions and Universal Joy English, mapped by the same unchanged rule) that maps to intensity variants and dyads (`skos:closeMatch` by an identical name or a listed adjective form, `skos:broadMatch` for GoEmotions only; unmapped labels carry a reason). Each dataset records how its labels were assigned (reader-annotated, writer-chosen, score-thresholded or distantly supervised), so competency questions can list which of the 48 Plutchik terms have a human-assigned label at all. A match by name does not establish that the dataset label and the Plutchik emotion are the same concept. Only label names and citations are included; no dataset text
- **Transfer evidence** (`ontology/plutchik-mapping-evidence.ttl`, generated by `build_transfer_evidence.py` from the numbers in `ontology/evidence/`) — for ordered pairs of name-matched labels from 19 datasets: how well a roberta-base classifier trained on one dataset's label separates the other dataset's label (AUC, the best other label's AUC, rank counts over 5 seeds). Three studies: the first (529 pairs, 10 datasets), a re-run that keeps the positives of rare labels in the training sample and records their number (532 pairs); for the two sources with rare labels (DailyDialog 'fear', GoEmotions 'pride') the first study's verdicts should be read together with the re-run (the re-run is not an independent replication); and a third study with 9 further datasets (1,029 pairs in which the source or the target is a new dataset), which also records the best AUC among the labels of *other basic emotions* and which of them it was. In the third study the per-pair verdict was not pre-registered (the rule of the re-run is applied unchanged), and the difference to the best other label depends on how many labels the source dataset has. It is evidence from one experimental setting, **not a judgement that a mapping is right or wrong**; the evidence does not change any mapping record. Only aggregate numbers are included (no dataset text; the datasets remain under their own licences). Limitations are in the study node's `skos:scopeNote`s and in `docs/MODELING_DECISIONS.md` §G and §H; queries are `ontology/evidence_cq.rq` (CQ-T1–T7; T7 lists, per basic emotion, which other basic emotion's label most often scored best against it — for disgust this is almost always anger, and for anger most often disgust).
- **7 derivation rules** — `min` at thresholds 0.3 / 0.5 / 0.7 (used by `infer_dyads.rq` for all 24 dyads), plus geometric / arithmetic mean, product and validation-calibrated variants
- **Labels and definitions in English and Japanese** for every term

It is authored **as an EFO module**: new terms attach to EFO / PROV-O / SKOS via
`rdfs:subClassOf`, `rdfs:subPropertyOf` and `skos:closeMatch` rather than reinventing
vocabulary. See [`docs/ONTOLOGY_CONSTRUCTION.md`](docs/ONTOLOGY_CONSTRUCTION.md).

## What is verifiable about it

Running the validator performs, all locally:

| Check | Artifact | Result |
|-------|----------|--------|
| Theory-graph structure (dyad composition and wheel distance, every non-opposite pair has exactly one dyad, opposites, adjacency, intensity variants) | `ontology/theory_shapes.ttl` | SHACL conforms |
| Logical consistency (basic / intensity variant / compound and the three dyad kinds pairwise disjoint) | OWL-RL closure | consistent |
| Documentation completeness (every term has label + definition in @en and @ja) | `ontology/doc_shapes.ttl` | 94/94 terms |
| Dataset label mappings (name-based scheme valid and every label covered; Lim & Cheong scheme audited) | `ontology/mapping_shapes.ttl`, `mapping_audit_shapes.ttl` | conforms; audit 1 violation / 2 warnings (known) |
| Transfer evidence (both records map to the same term, from two datasets; value ranges; verdict follows from the seed counts; no duplicates; the study states its limitations) | `ontology/evidence_shapes.ttl` | conforms (2,090 pairs in three studies; the verdict rule of each study is checked) |
| EFO alignment (`owl:imports` resolved against a local copy of EFO, fetched on first use from a pinned upstream commit and checked by SHA-256) | `ontology/efo-src/` (not in the repository) | 7/9 resolved (1 bridge, 1 open) |
| Provenance pipeline (occurrence → dyad inference → SHACL → 7 CQs) | `ontology/shapes.ttl`, `infer_dyads.rq`, `competency_questions.rq` | conforms, CQ-7 completeness = 0 |

The two non-resolved EFO terms are **known, documented modeling decisions**, not bugs —
see [`docs/MODELING_DECISIONS.md`](docs/MODELING_DECISIONS.md).

## Quick start

```bash
pip install -r requirements.txt          # rdflib, pyshacl, owlrl, numpy, pytest

python src/provenance/validate.py        # inference → SHACL → CQ + theory/doc/EFO checks
python -m pytest tests/ -q               # 98 tests, pure RDF (about 18 minutes; the evidence tests dominate)
python ontology/build_graph.py           # (optional) ontology → 16-node adjacency JSON
```

## Repository layout

```
ontology/
  efo-plutchik.ttl          TBox + individuals + derivation rules (the ontology)
  theory_shapes.ttl         SHACL: structural constraints on the theory graph
  doc_shapes.ttl            SHACL: every term carries rdfs:label + skos:definition
  shapes.ttl                SHACL: provenance/occurrence constraints (thesis pipeline)
  injection_shapes.ttl      SHACL: constraints on injection-provenance KGs
  infer_dyads.rq            SPARQL CONSTRUCT: derive dyad occurrences (min aggregation)
  competency_questions.rq   7 CQs (incl. CQ-7 provenance completeness)
  injection_cq.rq           CQs for injection-provenance KGs
  sample_occurrences.ttl    small sample occurrences for validation
  build_graph.py            ontology → plutchik_graph.json (adjacency; numpy only)
  efo-src/                  local cache of the EFO schema (EmoCore, BasicEmotions); not distributed,
                            fetched by validate.py from StenDoipanni/EFO@eeeda93 (upstream has no licence)
src/provenance/
  validate.py               the validation runner (rdflib + pyshacl + owlrl)
  to_rdf.py                 serialize attribution records → PROV-O provenance KG
scripts/build_docs.py       builds docs/index.html and the served copies of the ontology
releases/0.4.0/             the previous release of the ontology (owl:priorVersion)
tests/                      pure-RDF tests (EFO alignment, docs, theory graph, mappings, transfer evidence)
docs/                       reference page (GitHub Pages), served Turtle files by version,
                            construction notes, modeling decisions
w3id/                       redirect rules prepared for w3id.org (not registered yet; the namespace IRI
                            does not resolve — use the documentation URL above)
```
